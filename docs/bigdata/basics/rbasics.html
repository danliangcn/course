R、RStudio 与可重复的数据分析工作流

公共管理大数据分析：R语言基础

Published

September 14, 2026

本讲不是一份“R语法大全”，而是一次完整的数据分析入门。我们将围绕一份模拟的城市公共服务数据，完成从建立项目、导入数据、整理变量、分组汇总到制作图表的基本工作流。

本讲的核心原则

代码只是回答公共管理问题的工具。学习R时，应始终先问：我想用数据回答什么问题？

学习目标

完成本讲后，你应当能够：

  1. 区分 R、RStudio 与 Quarto 的作用；
  2. 使用 RStudio Project 和相对路径组织分析项目；
  3. 理解对象、向量、函数、逻辑判断和缺失值等最小语法；
  4. 使用 read_csv() 导入数据，并用 glimpse() 检查数据结构；
  5. 使用 filter()、select()、mutate()、group_by() 和 summarise() 整理数据；
  6. 使用 ggplot2 制作一张基本图表；
  7. 在遇到错误时，使用帮助文档、搜索和AI工具定位问题并验证结果。

1 R在这门课中做什么？

1.1 为什么公共管理需要R？

公共管理研究的数据来源正在从单一的问卷和统计年鉴，扩展到行政记录、政策文本、政务热线、空间数据、网络数据和平台行为数据。R可以帮助我们把数据处理、分析、可视化和报告写作连接成一个可重复的工作流。

在本课程中，R主要承担四类任务：

  • 整理数据：清洗变量、合并数据、处理缺失值；
  • 探索数据：描述分布、比较群体、识别异常；
  • 建立模型：回归、机器学习、文本、空间、网络和因果分析；
  • 沟通结果：制作图表，并用 Quarto 生成网页、报告和演示文稿。

1.2 R、RStudio与Quarto分别是什么？

工具 主要作用 可以把它理解为
R 执行统计计算和数据分析的语言 发动机
RStudio 编写代码、管理文件和查看结果的集成环境 驾驶舱
Quarto 将文字、代码、结果与图表整合为网页或报告 出版系统

三者的关系可以概括为：

flowchart LR
  A[公共管理问题] --> B[R代码]
  B --> C[分析结果]
  C --> D[Quarto网页或报告]
  E[RStudio项目] -.组织全过程.-> B
  E -.组织全过程.-> D

1.3 一条贯穿课程的分析主线

后续各专题虽然方法不同，但都遵循类似的分析过程：

公共管理问题 → 数据获取 → 数据整理 → 描述与可视化 → 建模与推断 → 政策解释与沟通

本讲先完成这条主线的最小版本。最终目标不是记住所有函数，而是能够独立完成一轮小型分析。

2 RStudio Project与可重复研究

2.1 一个研究问题，一个项目

建议为每个课程作业或研究问题建立一个 RStudio Project。一个简单的项目可以采用以下结构：

city-service-project/
├── data/                 # 原始数据和整理后的数据
├── R/                    # R脚本
├── figures/              # 图表
├── output/               # 表格和模型结果
├── report.qmd            # 分析报告
└── city-service-project.Rproj

在 RStudio 中依次选择：

File → New Project → New Directory → New Project

以后应通过 .Rproj 文件重新打开项目，而不是先打开某个脚本，再临时寻找数据文件。

2.2 使用相对路径

建立 Project 后，R会把项目根目录作为分析起点。读取文件时使用相对路径：

city_service <- read_csv("data/city_service.csv")

不推荐在项目脚本中使用只对自己电脑有效的绝对路径：

# 不推荐
setwd("/Users/your_name/Desktop/course")
city_service <- read_csv("/Users/your_name/Desktop/course/data/city_service.csv")

相对路径使同一项目更容易在不同电脑之间移动，也便于教师复现学生的分析结果。

可以用下面的命令查看当前工作目录，但通常不需要手动修改它：

getwd()

2.3 用脚本记录全过程

不要把分析过程只保存在 Console（控制台）或 Environment（环境）中。应将从原始数据到最终结果的操作写入脚本或 .qmd 文件，使别人能够从头重新运行。

建议的脚本命名方式如下：

01-import-data.R
02-clean-data.R
03-describe-data.R
04-model-data.R
05-make-figures.R

文件名应当：

  • 易于机器识别：避免空格和特殊符号；
  • 易于人类理解：看到文件名就知道用途；
  • 体现执行顺序：必要时在文件名前使用数字。

2.4 安装包与加载包

R包是扩展R功能的工具集合。安装通常只需进行一次：

install.packages("tidyverse")

每次重新启动R后，都需要加载本次分析使用的包：

library(tidyverse)
安装与加载不要混淆
  • install.packages() 类似“在电脑上安装软件”；
  • library() 类似“打开已经安装的软件”。

不要把 install.packages() 写在每次都会自动执行的分析文件中。

2.5 从第一行代码开始保持清晰

本课程采用三个基本代码风格：

# 1. 用 <- 赋值
target_year <- 2025

# 2. 对象名采用 snake_case
public_service_score <- 85

# 3. 运算符和逗号后留空格
mean_score <- mean(c(82, 85, 90), na.rm = TRUE)

这些规则不是为了形式整齐，而是为了让几周或几个月后的自己仍能读懂代码。

3 对象、向量与函数：够用的R语法

3.1 把一个值保存为对象

赋值符号 <- 可以把右侧的值保存到左侧命名的对象中。

city <- "厦门"
year <- 2025
satisfaction <- 90.2
digital_platform <- TRUE

city
[1] "厦门"
satisfaction
[1] 90.2

这里分别创建了字符、整数、数值和逻辑对象。R区分大小写，因此 city 与 City 是两个不同的对象。

3.2 向量：同类数据的集合

向量是R中最基本的数据结构。函数 c() 可以把多个值组合为一个向量。

complaints <- c(58400, 62000, 67000)
satisfaction <- c(84.1, 85.6, 87.3)

complaints
[1] 58400 62000 67000
mean(satisfaction)
[1] 85.66667

R的许多运算可以直接作用于整个向量：

population_10k <- c(846, 852, 858)
complaints_per_10000 <- complaints / population_10k

round(complaints_per_10000, 1)
[1] 69.0 72.8 78.1

上例中的人口单位为“万人”，所以“投诉量 ÷ 人口（万人）”直接得到每万人投诉量。

3.3 函数与参数

函数接受输入并返回结果。例如：

mean(satisfaction)
[1] 85.66667
round(mean(satisfaction), digits = 1)
[1] 85.7
  • mean() 和 round() 是函数；
  • 括号中的对象是函数的输入；
  • digits = 1 是参数，表示保留一位小数。

本阶段不需要记住大量函数。重点是能读懂：对哪个对象，调用了什么函数，使用了哪些参数。

3.4 逻辑判断

逻辑表达式返回 TRUE 或 FALSE，常用于筛选数据。

satisfaction > 85
[1] FALSE  TRUE  TRUE
city == "厦门"
[1] TRUE
city %in% c("福州", "厦门", "泉州")
[1] TRUE
运算符 含义
== 等于
!= 不等于
>、>= 大于、大于或等于
<、<= 小于、小于或等于
& 同时满足
\| 至少满足一个
! 取反
%in% 是否包含在一组值中

注意：= 常用于指定函数参数，== 用于判断两个值是否相等。

3.5 缺失值不是0

R使用 NA 表示缺失值。缺失不等于0，也不等于“没有”。

response_hours <- c(31.2, 27.4, NA, 22.8)

is.na(response_hours)
[1] FALSE FALSE  TRUE FALSE
mean(response_hours)
[1] NA
mean(response_hours, na.rm = TRUE)
[1] 27.13333

如果不明确处理缺失值，很多统计函数会返回 NA。参数 na.rm = TRUE 表示计算前移除缺失值。

不要机械删除缺失值

na.rm = TRUE 只解决计算问题，并没有解释数据为什么缺失。公共管理数据中的缺失可能来自未上报、选择性公开、系统更换或统计口径变化，应结合制度背景判断。

4 数据框与tidyverse工作流

4.1 数据框是什么？

公共管理数据通常以二维表格出现：每一行是一个观察对象，每一列是一个变量。

service_snapshot <- tibble(
  city = c("福州", "厦门", "泉州"),
  year = c(2025, 2025, 2025),
  population_10k = c(858, 540, 900),
  complaints = c(67000, 53000, 63000),
  satisfaction = c(87.3, 90.2, 85.1)
)

service_snapshot
# A tibble: 3 × 5
  city   year population_10k complaints satisfaction
  <chr> <dbl>          <dbl>      <dbl>        <dbl>
1 福州   2025            858      67000         87.3
2 厦门   2025            540      53000         90.2
3 泉州   2025            900      63000         85.1

这个数据框有3行、5列：

  • 行：城市—年份观察值；
  • 列：城市、年份、人口、投诉量和满意度等变量；
  • 单元格：某个观察对象在某个变量上的取值。

4.3 管道：把多个步骤连接起来

基础管道符 |> 把左侧结果传给右侧函数，使代码可以按分析顺序从上到下阅读。

service_snapshot |>
  filter(satisfaction >= 88) |>
  select(city, satisfaction)
# A tibble: 1 × 2
  city  satisfaction
  <chr>        <dbl>
1 厦门          90.2

可以把它读作：

从 service_snapshot 开始，然后筛选满意度不低于88的记录，然后保留城市和满意度两列。

4.4 五个核心数据处理函数

函数 作用 对数据的影响
filter() 按条件筛选观察值 减少行
select() 选择变量 减少列
mutate() 新建或修改变量 增加或改变列
group_by() 指定分组方式 改变后续计算单位
summarise() 计算汇总统计量 将多行压缩为摘要

下一节将用一份完整的模拟数据练习这些函数。

5 导入第一份公共管理数据

5.1 案例：城市公共服务回应

假设我们希望比较不同城市的政务热线办理效率，并讨论以下问题：

  1. 哪些城市的每万人投诉量较高？
  2. 各区域的平均满意度有何差异？
  3. 平均回应时间缩短时，满意度是否通常更高？

本讲使用一份教学模拟数据。数值仅为演示R工作流而构造，不代表任何城市的真实治理绩效，也不能用于实质性政策评价。

主要变量如下：

变量名 含义 单位/类型
city 城市 字符
region 区域 字符
year 年份 整数
population_10k 常住人口 万人
service_centers 便民服务中心数量 个
online_cases 政务热线受理量 件
closed_cases 按期办结量 件
satisfaction 群众满意度 %
avg_response_hours 平均首次回应时间 小时
pm25 PM2.5年均浓度 μg/m³

热线受理量既受治理问题数量影响，也受人口规模、平台可及性、公众投诉习惯和渠道整合方式影响。因此，受理量较高不能直接解释为“治理更差”。

6.5 汇总结果不等于因果结论

假如我们观察到回应时间短的城市满意度更高，只能说二者在这份数据中存在关联，不能直接断言：

缩短回应时间必然导致满意度提高。

城市财政能力、问题复杂度、平台使用群体和调查方式都可能同时影响回应时间与满意度。因果判断需要更合适的研究设计，这将在课程后续的政策评估部分讨论。

8 报错、帮助与AI辅助编程

8.1 先阅读错误信息

R报错并不意味着分析失败，而是在告诉你：代码、对象或数据与函数的预期不一致。

错误类型 常见原因 首先检查
找不到对象 对象尚未创建或名称拼错 Environment与变量名
找不到函数 相应R包未加载 library() 是否运行
找不到文件 路径错误或项目打开位置不对 Project与相对路径
非数值参数 数值列被读取为字符 glimpse() 输出
括号或引号错误 代码未闭合 报错行及其上一行

排错时建议保留完整错误信息，并从报错位置附近的小段代码开始检查。

8.2 使用R自带帮助

?mean
?read_csv
help.search("missing values")

如果不知道函数属于哪个包，可以搜索函数名和错误信息，也可以查看包的官方文档或示例。

8.3 使用AI辅助，但必须验证

AI适合帮助解释报错、逐行说明代码、提出排查顺序和生成小规模示例。一个较完整的提问应包含：

我在R中使用下面的代码分析城市公共服务数据。
请先解释错误原因，再给出最小修改，不要重写整个程序。

[粘贴可复现的代码]

[粘贴完整错误信息]

数据结构如下：
[粘贴 glimpse(data) 的输出]

建议遵循以下流程：

  1. 提供分析目标、代码、错误信息和必要的数据结构；
  2. 要求AI解释“为什么”，而不只是给出一段新代码；
  3. 在小数据上重新运行；
  4. 检查行数、变量类型、缺失值和关键统计量；
  5. 用帮助文档或其他可靠来源核对关键参数。
能运行不等于分析正确

AI可能生成不存在的函数、误解变量含义，或在没有研究设计依据时作出因果解释。研究者必须对数据处理过程、模型选择和实质性结论负责。

C.4 使用性能分析工具定位瓶颈

profvis 可以显示各段代码的运行时间和内存占用。下面示例不在网页渲染时自动执行：

library(profvis)

profvis({
  x <- 1:10000
  z <- 1.5

  multiplication <- function(x, z) {
    result <- c()
    for (i in seq_along(x)) {
      result <- c(result, x[i] * z)
    }
    result
  }

  result_loop <- multiplication(x, z)
  result_vectorized <- x * z
})

C.5 预先分配内存

在循环中不断增长对象，会触发重复的内存分配。已知输出长度时，应先创建足够长度的对象。

# 较慢：循环中持续增长对象
sqrt_vector <- function(x) {
  output <- c()
  for (i in seq_along(x)) {
    output <- c(output, sqrt(x[i]))
  }
  output
}

# 较快：预先分配输出长度
sqrt_vector_faster <- function(x) {
  output <- numeric(length(x))
  for (i in seq_along(x)) {
    output[i] <- sqrt(x[i])
  }
  output
}

}

C.7 理解对象复制

R通常采用“修改时复制”的机制。初始赋值可能让两个名称指向同一对象，修改其中一个对象后才发生复制。

a <- runif(10000)
b <- a

lobstr::obj_addr(a)
lobstr::obj_addr(b)

a[1] <- 0

lobstr::obj_addr(a)
lobstr::obj_addr(b)

处理大型数据时，应避免为了方便而创建大量完整副本。

C.8 释放不再使用的对象

可以删除不再需要的大型中间对象，并请求R进行垃圾回收：

# 仅作演示，不在网页渲染时创建大型对象
large_vector <- runif(10^8)

rm(large_vector)
gc()

通常不必频繁手动调用 gc()。更重要的是设计清晰的工作流，避免同时保留多个大型中间版本。

C.9 必要时采用更高效的工具

R的部分核心函数由C、C++或Fortran等编译型语言实现。面对真正的大规模数据，可以优先选择底层实现高效的工具，例如 data.table；如果数据无法全部载入内存，可以考虑 Arrow、DuckDB 或数据库查询。

工具选择应遵循由简到繁的顺序：

  1. 能否先明确问题并减少不必要的变量和记录？
  2. 能否用抽样数据开发和测试代码？
  3. 能否使用向量化函数或更高效的数据结构？
  4. 能否让 Arrow、DuckDB 或数据库只读取所需数据？
  5. 最后再考虑扩展硬件、云计算或分布式系统。
