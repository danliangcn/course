数据描述与可视化

从公共管理问题到可信的数据图形

发布于

2026年10月12日

本讲要解决的问题

数据可视化不仅是“把数据画出来”，而是把公共管理问题、统计证据和政策沟通连接起来。本讲围绕一份模拟的某市 12345 政务热线数据，完成以下过程：

明确问题 → 判断变量 → 选择图形 → 完成图形 → 检查误导 → 解释结果

课堂原则：一图一问一结论

每张图都必须回答一个明确问题，并附上一句主要发现和一句限制。图形漂亮不等于证据可靠。

0.0.1 学习目标

完成本讲后，你应该能够：

  1. 根据研究问题和变量类型选择合适的图形；
  2. 理解 ggplot2 的数据、映射、几何对象、刻度、标签和主题；
  3. 绘制并解释条形图、点图、直方图、箱线图、散点图和折线图；
  4. 使用分组、切片和误差线表达比较与不确定性；
  5. 识别坐标轴、分母、颜色、缺失值和因果表述造成的误导；
  6. 输出一份可直接用于课程项目的“三图一表”简报。

1 进入课堂：激活已有知识

1.1 3分钟检索练习

不运行代码，独立回答：

  1. filter()、group_by() 和 summarise() 分别改变数据的什么部分？
  2. 为什么比较各区县热线诉求时，案件总量和每万人案件量可能给出不同结论？
  3. NA 会怎样影响 mean()？
  4. 一行数据在热线案件表中代表什么？
参考答案
  1. filter() 选择行，group_by() 建立分组，summarise() 把多行压缩成汇总结果。
  2. 各区县人口规模不同，总量较高可能只是人口较多。
  3. 默认返回 NA，通常需要结合数据含义决定是否使用 na.rm = TRUE。
  4. 一行代表一个热线案件；分析单位改变时，图形和解释也必须改变。

2 教学数据与最低限度检查

上一讲已经完成数据获取与清理，本讲不再重复导入格式、缺失值插补和复杂重塑。为了使本页面可以独立渲染，下面生成一份与上一讲相同情境的模拟教学数据。

展开：生成本讲使用的模拟热线数据 
# 本代码块只用于生成可重复的教学数据，
# 学生不需要在本讲掌握随机数据生成方法。
set.seed(20250928)

n_cases <- 480
policy_date <- as.Date("2025-04-15")

hotline <- tibble(
  case_id = sprintf("C%04d", 1:n_cases),
  submitted_date = as.Date("2025-03-01") +
    sample(0:90, n_cases, replace = TRUE),
  district = sample(
    c("思明区", "湖里区", "集美区", "海沧区", "同安区", "翔安区"),
    n_cases,
    replace = TRUE,
    prob = c(.20, .19, .18, .13, .16, .14)
  ),
  issue_type = sample(
    c("市容环境", "交通出行", "公共服务", "住房建设"),
    n_cases,
    replace = TRUE,
    prob = c(.34, .28, .23, .15)
  ),
  channel = sample(
    c("电话", "微信", "网站"),
    n_cases,
    replace = TRUE,
    prob = c(.46, .34, .20)
  )
) |>
  mutate(
    issue_delay = case_when(
      issue_type == "住房建设" ~ 12,
      issue_type == "公共服务" ~ 7,
      issue_type == "交通出行" ~ 4,
      TRUE ~ 0
    ),
    response_hours = rgamma(n_cases, shape = 2.4, scale = 6) + issue_delay,
    response_hours = if_else(
      submitted_date >= policy_date,
      response_hours * 0.78,
      response_hours
    ),
    response_hours = round(response_hours, 1),
    status = if_else(
      submitted_date > max(submitted_date) - 7 & runif(n_cases) < .35,
      "处理中",
      "已办结"
    ),
    satisfaction_score = round(
      4.4 - response_hours / 28 + rnorm(n_cases, 0, .65)
    ),
    satisfaction_score = pmin(4, pmax(1, satisfaction_score)),
    missing_probability = case_when(
      status == "处理中" ~ .75,
      channel == "网站" ~ .28,
      TRUE ~ .12
    ),
    satisfaction_score = if_else(
      runif(n_cases) < missing_probability,
      NA_real_,
      as.numeric(satisfaction_score)
    )
  ) |>
  select(
    case_id, submitted_date, district, issue_type,
    response_hours, status, satisfaction_score, channel
  )

关于模拟数据

本页所有数值仅用于教学。政策节点前后的差异是模拟设置，不能被当作真实政策效果，也不能据此形成实际城市排名。

2.2 用图形检查缺失情况

上一讲已经用代码计算缺失数量和缺失比例。本讲进一步把审计结果画出来，以便快速发现缺失集中的变量。

missing_by_variable <- hotline |>
  summarise(
    across(
      everything(),

      # is.na(.x) 判断当前变量的每个值是否缺失。
      # mean() 把 TRUE 当作1、FALSE当作0，
      # 因此结果就是该变量的缺失比例。
      ~ mean(is.na(.x))
    )
  ) |>

  # summarise() 生成的是一行多列的宽表。
  # pivot_longer() 将变量名和缺失率整理成两列，便于ggplot绘图。
  pivot_longer(
    everything(),
    names_to = "variable",
    values_to = "missing_rate"
  ) |>

  # 让缺失率最高的变量排在前面。
  arrange(desc(missing_rate))

3 先选择图形，再写代码

3.1 问题—变量—图形

想回答的问题 主要变量 推荐图形
哪类案件最多？ 一个类别变量 排序条形图
哪个地区的标准化指标更高？ 类别＋比率 点图或条形图
回应时间如何分布？ 一个数值变量 直方图或箱线图
不同事项的回应时间是否不同？ 类别＋数值 箱线图＋抖动点
两个数值变量是否相关？ 两个数值变量 散点图＋趋势线
指标如何随时间变化？ 日期＋数值 折线图
各组构成是否不同？ 两个类别变量 百分比堆叠条形图
估计值有多精确？ 分组估计＋区间 点图＋误差线

3.2 12分钟图形诊断

对下面四种做法作出判断，并说明理由：

  1. 用饼图比较12个部门的案件占比；
  2. 用案件总量评价人口不同的区县；
  3. 用折线连接没有时间顺序的四类事项；
  4. 用散点图中的拟合线证明回应速度提高了满意度。
诊断提示
  1. 类别过多时角度和面积难以比较，排序条形图通常更清楚；
  2. 应同时考虑人口、服务对象或其他合理分母；
  3. 折线暗示连续顺序，不适合无序类别；
  4. 拟合线只能显示相关模式，不能自动排除选择偏差和混杂因素。

5.1 哪类诉求最多？

先汇总，再使用 geom_col()：

issue_counts <- hotline |>

6.3 用箱线图规则标记极端观测

箱线图通常把低于 \(Q_1-1.5\times IQR\) 或高于 \(Q_3+1.5\times IQR\) 的观测标记为极端值。下面在每种事项类型内部计算这一规则。

hotline_extreme <- hotline |>

  # 不同事项的正常回应时间可能不同，
  # 因此在每种 issue_type 内部分别计算四分位数。
  group_by(issue_type) |>
  mutate(

    # 第一四分位数：25%的案件低于这个值。
    q1 = quantile(response_hours, .25, na.rm = TRUE),

    # 第三四分位数：75%的案件低于这个值。
    q3 = quantile(response_hours, .75, na.rm = TRUE),

    # 四分位距 IQR = Q3 - Q1。
    iqr = q3 - q1,

    # 计算箱线图上下界。
    lower_limit = q1 - 1.5 * iqr,
    upper_limit = q3 + 1.5 * iqr,

    # 只要超出任意一侧界限，就标记为统计极端值。
    statistical_extreme =
      response_hours < lower_limit |
      response_hours > upper_limit
  ) |>

  # 取消分组，避免后续操作继续按事项类型分别执行。
  ungroup()

6.4 统计极端值不等于录入错误

情形 判断依据 推荐处理
回应时间为负数 不符合时间逻辑 回查日期和单位，确认后修正或设为缺失
回应时间很长，但对应复杂积案 业务上可能真实存在 保留，必要时单独解释
数值比同组高，但原始记录完整 只是统计极端 保留并进行稳健性分析
小时误填成分钟或相反 单位和其他记录不一致 回查后统一单位
无法回查来源 无法判断真实性 标记为待核查，比较保留与排除后的结果

可以把“违反业务规则”和“统计上极端”分成两个变量：

    )

11.4 可信图形检查表

提交图形前逐项检查：

  • 问题、分析单位和分母是否明确？
  • 图形类型是否符合变量类型？
  • 是否诚实显示缺失值、异常值和样本量？
  • 坐标轴、单位、图例和时间范围是否完整？
  • 颜色是否有意义，并兼顾色觉差异？
  • 标题是否陈述了超过证据范围的结论？
  • 是否把相关关系写成因果关系？
  • 是否注明数据来源和模拟数据身份？

14 本讲小结

可信的数据可视化需要同时做到：

  1. 问题先于图形：先确定想比较、描述还是解释什么；
  2. 变量决定图形：类别、数值和时间变量使用不同视觉表达；
  3. 分母决定含义：总量、比例和率回答不同问题；
  4. 展示数据结构：尽量保留分布、样本量和不确定性；
  5. 避免视觉误导：谨慎处理坐标轴、缩放、颜色和缺失值；
  6. 限制因果语言：趋势和相关图主要用于描述与提出问题；
  7. 代码能够复现：图形、数据和文字解释保持一致。

theme_course <- function(base_size = 13, base_family = cn_family) {
  theme_minimal(base_size = base_size, base_family = base_family) +
    theme(
      plot.title.position = "plot",
      plot.title = element_text(face = "bold"),
      panel.grid.minor = element_blank(),
      legend.position = "bottom",
      axis.title = element_text(color = "grey25"),
      plot.caption = element_text(color = "grey45", hjust = 0)
    )
}

ggplot(issue_counts, aes(x = n, y = reorder(issue_type, n))) +
  geom_col(fill = "#2C7FB8") +
  labs(
    title = "热线事项数量",
    x = "案件数",
    y = NULL,
    caption = "数据：模拟12345政务热线数据"
  ) +
  theme_course()

主题只调整非数据元素，不能补救错误的指标、分母或图形类型。

18 附录D：出版与无障碍输出

正式图形还应注意：

  • 避免仅依赖红色和绿色区分类别；
  • 保证文字、线条与背景有足够对比度；
  • 在网页中提供简短替代文本；
  • 为论文输出300 dpi以上的PNG或矢量PDF；
  • 固定输出尺寸，避免每次渲染比例不同；
  • 说明数据来源、时间范围和处理口径。

Quarto代码块可以加入替代文本：

#| fig-alt: "排序条形图显示四类热线事项数量，市容环境类最高。"

输出PDF图形时，如果中文字体兼容性不稳定，优先确认 showtext 已启用，避免绑定某台电脑的绝对字体路径。
