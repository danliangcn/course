机器学习（一）：基本概念、应用场景与泛化

以12345诉求逾期风险预警为例

发布于

2026年10月19日

本讲的中心问题

机器学习不是简单地“选择一个算法并运行代码”。它研究的是：怎样利用已有案例学习稳定的规律，并对尚未见过的案例作出尽可能可靠的预测。

2 第1课时：机器学习在学习什么、能够解决什么？

2.1 机器学习的基本定义

机器学习可以理解为：计算机利用已有数据改进某项任务表现的方法。一个机器学习问题通常包含三部分：

  • 任务（task）：希望机器完成什么，例如判断一条新工单是否可能逾期；
  • 经验（experience）：可供学习的历史案例，例如过去工单的特征和实际办结结果；
  • 表现（performance）：用什么标准判断学得好不好，例如能否识别实际逾期工单。

对于监督学习，可以用下面的形式表示：

\[ Y = f(X) + \varepsilon \]

其中，\(X\) 是一组输入特征，\(Y\) 是希望预测的目标，\(f\) 是两者之间的未知关系，\(\varepsilon\) 是当前数据无法解释的随机性和测量误差。

机器学习不是寻找现实中唯一正确的 \(f\)，而是利用有限数据估计一个 \(\hat f\)，使它对新案例的预测尽可能准确。

2.2 数据、算法与模型不是同一个概念

概念 含义 本讲例子
观测 数据中的一个分析单位 一条12345工单
特征 预测时可使用的输入变量 诉求类型、积压量、值班人数
目标 希望预测的结果 是否超过48小时办结
算法 从数据中估计规律的计算步骤 估计逻辑回归系数的过程
模型 对输入与目标关系的表达形式 逾期概率是多个特征的函数
拟合模型 用具体训练数据估计后的模型 已经得到系数的逻辑回归
参数 从训练数据中学习得到的数值 逻辑回归系数
超参数 训练前设定或通过重采样选择的配置 树深、KNN的邻居数

“逻辑回归”可以指一种模型形式；软件根据训练数据估计系数，是算法执行的过程；得到具体系数后，才形成可用于预测的拟合模型。

2.3 公共管理与公共政策的应用地图

机器学习适合处理具有较多历史案例、可观察特征和明确任务的数据问题。它既可以服务政府内部管理，也可以服务政策研究。

领域 示例问题 任务类型 可能的数据 特别需要警惕
社会救助 哪些家庭可能在近期再次申请救助？ 二分类 申请记录、就业、家庭结构 历史排除与群体污名
公共卫生 哪些患者存在再次入院风险？ 二分类 就诊、诊断、用药、随访 隐私、遗漏弱势群体
环境治理 明日PM2.5浓度是多少？ 回归 监测、气象、排放、交通 时间和空间依赖
城市运行 哪些12345工单可能逾期？ 二分类 工单、积压量、人员、时段 模型用于辅助还是处罚
应急管理 哪些区域更可能发生积涝？ 分类或回归 降雨、地形、管网、历史灾情 极端事件样本稀少
财政监管 哪些采购项目可能异常？ 异常识别或分类 招标、合同、供应商网络 异常不等于违法
教育治理 哪些学生存在失学或辍学风险？ 二分类 出勤、成绩、家庭与资助 标签可能带来歧视
公共人力资源 哪些岗位可能出现人员流失？ 二分类 岗位、工作负担、流动记录 人事决策公平性
公共交通 下一时段的客流量是多少？ 回归 刷卡、线路、天气、节假日 突发事件与分布变化
政策文本 一份文件属于哪个政策议题？ 多分类 政策文件、条款和元数据 标签标准与语义漂移
政民互动 大量留言包含哪些诉求类型？ 聚类或主题识别 留言、回复与时间信息 沉默人群不会出现在数据中
空间治理 哪些区域可能出现违法用地？ 分类 遥感、地籍、审批、巡查 空间误差与执法后果

2.3.1 从应用场景中识别三类价值

  • 预测与预警：提前识别风险、需求或工作量；
  • 分类与自动辅助：给文本、图像或案件分配类别，帮助人工处理；
  • 模式发现：从大量对象中发现群组、异常或低维结构。

机器学习也有明显边界：历史数据不可得、目标无法可靠测量、干预会改变行为、错误后果极高或需要回答因果问题时，不能仅靠提高算法复杂度解决。

2.3.2 课堂检查1：把研究问题写成机器学习任务

任选一个应用场景，依次写出：

  1. 分析单位是什么？
  2. 目标变量是什么？
  3. 在什么时点作出预测？
  4. 当时能够使用哪些特征？
  5. 预测错误会造成什么后果？

只有能够回答这五个问题，一个宽泛的公共管理议题才初步变成可执行的预测任务。

2.4 监督学习与无监督学习

2.4.1 监督学习

训练数据中包含目标变量，目标值为模型学习提供“监督”。监督学习主要包括：

  • 回归（regression）：预测连续数值，如响应时间、财政支出或污染浓度；
  • 分类（classification）：预测类别或类别概率，如是否逾期、是否重复投诉、风险等级。

分类模型通常先给出概率，再根据阈值转成类别。例如逾期概率为0.68，若阈值为0.50，就归为“逾期风险”。

2.4.2 无监督学习

训练数据没有预先给定的目标变量，分析者希望发现数据内部结构：

  • 聚类：把特征相似的居民、地区或诉求分成若干群组；
  • 降维：把多个相关指标压缩成较少的综合维度；
  • 异常识别：寻找与多数案例差异明显的观测。

无监督学习没有明确的“标准答案”，结果通常需要结合稳定性、可解释性和领域知识评价。

2.5 回归与分类取决于目标

公共管理问题 目标变量 任务类型
预测一条诉求需要多少小时办结 连续数值 回归
预测一条诉求是否超过48小时 两个类别 二分类
预测诉求的低、中、高风险等级 三个类别 多分类
根据服务需求对社区进行分群 没有目标变量 无监督聚类

“回归问题”是一类预测任务，不等同于“线性回归算法”。决策树、随机森林和神经网络也能解决回归问题。

2.5.1 课堂检查2：判断任务类型

  1. 预测下个月各区县的投诉数量；
  2. 判断一条新诉求是否可能重复投诉；
  3. 按公共服务需求把社区划分成不同类型；
  4. 评估增加值班人员是否缩短响应时间。
参考答案
  1. 回归；2. 分类；3. 聚类；4. 因果问题。第四个问题关心“采取行动后结果是否改变”，不能仅凭预测模型回答。

2.6 预测、描述与因果推断

目的 典型提问 判断标准
描述 哪类诉求的逾期率最高？ 是否准确概括已有数据
预测 哪些新工单可能逾期？ 对新数据的预测是否准确
因果 增加工作人员能否减少逾期？ 是否识别干预造成的变化

一个变量对预测很有帮助，并不意味着改变它一定能改变结果。例如，“深夜来电”可能与逾期相关，但把来电时间改成白天并不一定消除真正原因。

2.7 定义本讲的预测任务

假设某市12345热线希望在工单受理时，识别可能超过48小时仍未办结的诉求，以便进入人工复核或优先分派队列。

要素 本讲设定
分析单位 一条刚进入系统的12345工单
预测时点 工单登记完成、尚未办理时
目标变量 是否超过48小时办结：late_48h
可用特征 区县、诉求类型、渠道、紧急程度、积压量等
模型输出 逾期概率及风险类别
后续行动 人工复核、提醒或优先分派，而非自动处罚
预测时点决定特征边界

如果模型在“受理时”预测，就不能使用办结后才知道的信息，例如实际办结时长、最终满意度或是否退回。使用这些信息会造成数据泄漏。

2.8 生成自带的模拟数据

下面的数据由代码生成，不需要下载外部文件，仅用于教学。

set.seed(2026)
# 固定随机种子后，教师和学生会得到同一份模拟数据。
n <- 1500

hotline_raw <- tibble(
  # sprintf() 把编号补足为5位，例如 CASE-00001。
  case_id = sprintf("CASE-%05d", 1:n),
  # 从半年内的每个小时随机抽取工单受理时间。
  received_at = sample(
    seq.POSIXt(
      as.POSIXct("2025-01-01 00:00:00"),
      as.POSIXct("2025-06-30 23:00:00"),
      by = "hour"
    ),
    size = n,
    replace = TRUE
  ),
  district = sample(
    c("思明区", "湖里区", "集美区", "海沧区", "同安区", "翔安区"),
    n, replace = TRUE,
    prob = c(0.22, 0.20, 0.18, 0.13, 0.14, 0.13)
  ),
  issue_type = sample(
    c("市政设施", "环境卫生", "住房物业", "交通出行", "社会保障"),
    n, replace = TRUE,
    prob = c(0.22, 0.20, 0.24, 0.19, 0.15)
  ),
  channel = sample(
    c("电话", "网站", "微信", "政务App"),
    n, replace = TRUE,
    prob = c(0.42, 0.18, 0.25, 0.15)
  ),
  urgent = sample(c("否", "是"), n, replace = TRUE, prob = c(0.82, 0.18)),
  repeat_case = sample(c("否", "是"), n, replace = TRUE, prob = c(0.76, 0.24)),
  # pmax(0, ...) 保证积压量不会出现负数。
  backlog = pmax(0, round(rnorm(n, mean = 22, sd = 9))),
  staff_on_duty = sample(4:12, n, replace = TRUE),
  # 对数正态分布可以模拟“多数文本较短、少数文本很长”的情况。
  text_length = pmax(20, round(rlnorm(n, log(115), 0.55)))
) |>
  mutate(
    # 从日期时间中提取在受理时已经知道的特征。
    hour = lubridate::hour(received_at),
    weekday = lubridate::wday(
      received_at, label = TRUE, abbr = FALSE, week_start = 1
    ),
    holiday_or_weekend = if_else(
      lubridate::wday(received_at, week_start = 1) >= 6, "是", "否"
    ),
    # 隐藏规则只用于生成模拟结果，不会提供给模型。
    risk_score =
      -2.25 +
      0.85 * (urgent == "是") +
      0.70 * (repeat_case == "是") +
      0.045 * backlog -
      0.10 * staff_on_duty +
      0.45 * (issue_type == "住房物业") +
      0.30 * (issue_type == "社会保障") +
      0.35 * (district == "翔安区") +
      0.30 * (holiday_or_weekend == "是"),
    late_probability = plogis(risk_score),
    # 每条工单按各自概率随机生成“按时/逾期”结果。
    late_48h = if_else(runif(n) < late_probability, "逾期", "按时"),
    # 办结后才产生，不能用于受理时预测。
    actual_close_hours = if_else(
      late_48h == "逾期", runif(n, 49, 120), runif(n, 2, 48)
    )
  ) |>
  select(-risk_score, -late_probability)

# 模拟少量缺失记录。
set.seed(2027)
hotline_raw$backlog[sample(seq_len(n), 35)] <- NA
hotline_raw$channel[sample(seq_len(n), 22)] <- NA

hotline_raw
如何理解运行结果？

输出是一张包含1,500条模拟工单的 tibble。每一行是一条工单，每一列是一项属性。页面只显示部分行和部分列，并不表示其他数据没有生成。case_id 是标识符，late_48h 是目标变量，actual_close_hours 是故意保留的泄漏变量。此时看到的只是原始建模数据，还没有划分训练集，也没有训练模型。

  • duplicated_ids 应为0；若大于0，说明一条工单可能出现多行，必须先判断是重复记录还是“一对多”的业务结构。
  • 缺失统计中，backlog 和 channel 会大于0，这是后面演示填补和未知类别处理的依据。
  • 目标比例用于判断类别是否平衡。若“逾期”明显少于“按时”，高准确率可能只是多数类造成的假象。

3 第2课时：从拟合历史数据到预测新案例

3.1 训练、损失与经验风险

模型训练是利用训练数据寻找参数，使预测与真实目标之间的差异尽量小。这种差异由损失函数衡量。

对于回归，常见的平方误差是：

\[ L(y, \hat y)=(y-\hat y)^2 \]

训练过程可以概括为：

\[ \hat f=\arg\min_f\frac{1}{n}\sum_{i=1}^{n}L(y_i,f(x_i)) \]

分类模型通常先预测类别概率，再用对数损失等函数衡量概率与真实类别之间的差异。

3.2 泛化、欠拟合与过拟合

训练误差小并不等于模型好。机器学习真正关心的是泛化：面对未参与训练的新数据时，模型是否仍能保持较好表现。

状态 训练数据表现 新数据表现 典型原因
欠拟合 较差 较差 模型太简单，重要关系未学到
合理拟合 较好 较好 学到相对稳定、可重复的规律
过拟合 很好 较差 过度适应训练样本中的噪声

过拟合并不是由“训练集超过80%”直接造成的。它通常与模型复杂度、样本量、特征数量、噪声、反复调参和数据泄漏有关。

3.2.1 偏差—方差的直观解释

  • 偏差：模型假设过强造成的系统性误差，模型过于简单时往往较高；
  • 方差：模型对训练样本变化的敏感程度，模型过于复杂时可能较高；
  • 不可约误差：在现有特征和测量条件下无法消除的随机性。

模型选择不是追求训练误差最低，而是在偏差与方差之间寻找有利于新数据表现的平衡。

3.3 训练集、重采样和测试集

数据角色 用途 是否用于模型选择
训练集 估计模型参数，建立预处理规则 是
重采样验证数据 比较模型、选择超参数、估计波动 是
测试集 最终评价泛化表现 否，只在最后使用一次

测试集如果被反复查看，就会逐渐成为模型选择的一部分，不再是独立评价。

3.4 准备并划分数据

hotline_model <- hotline_raw |>
  mutate(
    # 将目标改成因子，并把“逾期”放在第二个水平。
    # 后续 event_level = "second" 就表示把“逾期”视为关注事件。
    late_48h = factor(late_48h, levels = c("按时", "逾期")),

  hotline_model,

test_data  <- testing(hotline_split)

tibble(
  dataset = c("训练集", "测试集"),
  rows = c(nrow(train_data), nrow(test_data)),
  late_rate = c(
    mean(train_data$late_48h == "逾期"),
    mean(test_data$late_48h == "逾期")

如何理解划分结果？

训练集应约占总样本的75%，测试集约占25%。两部分的 late_rate 应非常接近，说明分层划分发挥了作用。这里的75%并不是固定标准；关键是训练集足以学习规律，同时测试集足以形成较稳定的最终评价。测试集从此应暂时封存。

随机划分不是唯一选择

若预测未来月份，应优先考虑时间划分；若同一居民、企业或地区有多条记录，应考虑分组划分，避免同一对象同时进入训练集和测试集。相关代码见附录。

3.5 交叉验证如何估计泛化表现？

在 \(k\) 折交叉验证中，训练集被分为 \(k\) 份：每次用一份验证，其余部分训练，循环后汇总结果。它能够在不接触测试集的情况下比较模型、选择超参数并观察表现波动。

set.seed(2026)
# v = 5 表示创建5折；每次用4折训练、1折验证。
# strata 再次保证每一折的目标类别比例大致稳定。
hotline_folds <- vfold_cv(
  train_data,
  v = 5,
  strata = late_48h
)

# 打印对象时会看到 Fold1 至 Fold5 以及各自的划分对象。
hotline_folds
如何理解交叉验证输出？

输出中的每一行代表一次重采样划分，而不是一条原始工单。splits 保存该折的分析集和评估集，id 标明折号。此时模型尚未训练；这里只是提前制定一套在训练集内部反复训练和验证的计划。

3.6 先建立朴素基准

如果多数工单按时办结，一个始终预测“按时”的模型也可能有较高准确率。复杂模型至少应与这个基准比较。

majority_class <- train_data |>
  # 统计训练集中两个类别的数量，并按数量从高到低排列。
  count(late_48h, sort = TRUE) |>

  slice(1) |>
  pull(late_48h) |>
  as.character()

baseline_pred <- train_data |>
  mutate(
    # 不看任何特征，对所有测试工单都预测成训练集中的多数类。

# 先显示模型始终预测的类别。

如何理解基准结果？

majority_class 通常为“按时”，所以模型对所有训练工单都给出同一个答案。其准确率等于训练数据中“按时”工单的比例；特异度可能很高，但敏感度为0，因为它没有识别出任何实际逾期工单。这里的结果只是说明基准规则，最终比较仍应在同一份测试数据上进行。后续模型不仅要关注基准准确率，更重要的是要真正识别少数类。

3.7 把预处理写入 recipe

recipes 包把数据预处理写成一份可重复执行的“配方”。它解决两个问题：哪些变量进入模型，以及这些变量按什么顺序转换。

一份 recipe 通常经历三个阶段：

  1. recipe() 声明目标、预测变量和处理步骤，此时只是设计方案；
  2. prep() 用训练数据估计方案中需要学习的数值，例如中位数、类别水平和哑变量列；
  3. bake() 把已经估计好的规则应用到训练数据或新数据。

在正式建模时，不需要手工调用 prep() 和 bake()；把 recipe 加入 workflow 后，tidymodels 会在每一个交叉验证折中自动完成它们。这样可以避免用验证集或测试集计算填补值，从而减少数据泄漏。

本讲的处理顺序如下：

步骤 处理对象 作用
step_impute_median() 数值特征 用训练样本中位数填补缺失值
step_unknown() 分类特征 把原有缺失值转换为“未知”类别
step_novel() 分类特征 接纳新数据中训练时未见过的类别
step_dummy() 分类特征 将文字类别转换为模型可使用的0/1变量
step_zv() 全部特征 删除完全没有变化、没有预测信息的变量 
hotline_recipe <- recipe(
  # 公式左边是目标，右边列出预测时允许使用的特征。
  late_48h ~ district + issue_type + channel + urgent +
    repeat_case + backlog + staff_on_duty + text_length +
    hour + weekday + holiday_or_weekend,
  # data 用于识别变量类型和角色；这里必须是训练数据。
  data = train_data
) |>
  # all_numeric_predictors() 只选择数值型预测变量，不会处理目标变量。
  step_impute_median(all_numeric_predictors()) |>
  # all_nominal_predictors() 选择因子或字符型预测变量。
  step_unknown(all_nominal_predictors()) |>
  step_novel(all_nominal_predictors()) |>
  step_dummy(all_nominal_predictors()) |>
  step_zv(all_predictors())

# 打印的是“尚未估计”的处理方案，而不是处理后的数据。
hotline_recipe

打印结果中的 Operation 列列出预处理步骤；Trained 通常显示 FALSE，说明当前只是配方，还没有计算中位数或建立哑变量。

3.8 定义逻辑回归及工作流

逻辑回归预测事件概率：

\[ P(Y=1\mid X)=\frac{1}{1+e^{-(\beta_0+\beta_1X_1+\cdots+\beta_pX_p)}} \]

逻辑函数把任意线性组合转换到0与1之间。本讲将它作为透明的基准学习模型；系数和正则化将在下一讲展开。

logistic_model <- logistic_reg() |>
  # 使用R自带的广义线性模型引擎估计逻辑回归。
  set_engine("glm") |>
  # 明确这是分类任务，而不是连续结果回归。
  set_mode("classification")

logistic_workflow <- workflow() |>
  # workflow 将数据预处理方案与模型规格绑定在一起。
  add_recipe(hotline_recipe) |>
  add_model(logistic_model)

cv_metrics <- collect_metrics(cv_results)

如何阅读交叉验证结果？
  • .metric 是指标名称；.estimate 类型说明是二分类指标；
  • mean 是5个验证折的平均值，是当前对新数据表现的主要估计；
  • n 是成功参与汇总的折数，正常情况下为5；
  • std_err 越大，说明不同折之间表现越不稳定。

ROC AUC 接近0.5表示区分能力接近随机排序，越接近1越好。敏感度和特异度需要一起看：如果准确率较高但敏感度很低，模型仍然可能漏掉大部分逾期工单。交叉验证结果用于比较和修改模型，不是最终对外报告的测试表现。

3.10 分类指标的含义

把“逾期”视为需要识别的事件：

指标 回答的问题 局限
准确率 全部工单中预测正确多少？ 类别不平衡时可能虚高
敏感度 实际逾期工单中识别出多少？ 提高时可能带来更多误报
特异度 实际按时工单中正确排除多少？ 不能反映漏报情况
ROC AUC 模型区分两类工单的总体能力如何？ 不直接给出行动阈值

指标必须结合任务选择。若漏掉高风险工单代价较大，应特别关注敏感度；若误报会直接引发处罚，则应更谨慎地控制误报。

如何理解测试结果？

测试指标是模型面对完全未参与训练和选择的数据时的最终表现。应先与交叉验证的 mean 比较：数值接近说明重采样估计较稳定；测试表现明显较差可能意味着模型选择过度适应训练数据，也可能只是测试样本带来的随机波动。一次测试结果不是永恒结论，真实部署后还需要持续监测。

test_pred 中的 .pred_逾期 是模型给出的逾期概率，.pred_class 是根据默认阈值形成的类别。概率保留的信息比单一类别更多，后续可用于风险排序和阈值选择。

最后的比较表将多数类基准和逻辑回归放在同一测试集上。若逻辑回归的敏感度明显高于0，说明它开始能够识别逾期工单；如果与此同时特异度下降，说明这种识别能力是以增加部分误报为代价取得的。

3.12 混淆矩阵：模型错在什么地方？

# truth 指定真实结果，estimate 指定模型预测结果。
conf_mat(test_pred, truth = late_48h, estimate = .pred_class)
#>           Truth
#> Prediction 按时 逾期
#>       按时  287   73
#>       逾期   10    5
  • 漏报：实际逾期，却预测为按时；
  • 误报：实际按时，却预测为逾期。

两类错误的治理成本往往不同。模型评价不是寻找脱离情境的“最高分”，而是判断错误能否被实际管理过程接受和纠正。

如何阅读混淆矩阵？

先查看输出中标明的 Truth 和 Prediction 方向，不要凭位置猜测。对角线是预测正确的工单，非对角线是错误。真实“逾期”但预测“按时”的单元格是漏报；真实“按时”但预测“逾期”的单元格是误报。将单元格数量与业务成本结合，通常比只报告准确率更有管理含义。

3.12.1 课堂检查4：解释而不是抄写输出

  1. 逻辑回归是否优于多数类基准？依据是什么？
  2. 当前模型更容易漏报还是误报？
  3. 为什么不能根据测试集结果反复修改预处理和模型？
  4. 如果模型只用于人工复核而不是自动处罚，指标选择会有什么不同？

4 本讲总结

  1. 机器学习利用历史经验改进任务表现；
  2. 公共管理中的预测、分类、异常识别和模式发现均可使用机器学习；
  3. 监督学习拥有目标变量，无监督学习主要发现数据结构；
  4. 回归预测连续数值，分类预测类别或概率；
  5. 算法是学习过程，拟合模型是学习后的结果；
  6. 训练误差低不等于泛化能力强；
  7. 重采样用于模型选择，测试集只承担最终评价；
  8. 评价模型必须结合指标、错误成本和使用情境；
  9. 预测关系不自动等于因果关系。

5.1 重复交叉验证

一次 \(k\) 折交叉验证仍受随机分折影响。重复交叉验证多次重新分折，可以更稳定地观察平均表现及波动，但会增加计算时间。

set.seed(2026)
repeated_folds <- vfold_cv(
  train_data, v = 5, repeats = 3, strata = late_48h
)

5.2 自助法

自助法从原数据中有放回抽样。某些观测会被抽到多次，未被抽中的观测可用于评价。它常用于估计统计量不确定性，也可用于模型评价。

set.seed(2026)
bootstrap_samples <- bootstraps(
  train_data, times = 100, strata = late_48h
)

6 附录B：偏差—方差与模型复杂度

随着模型复杂度增加，训练误差通常下降，偏差可能下降，但方差可能上升；测试误差往往先下降、后上升。因此不能用训练误差选择复杂度。

学习曲线可以比较不同样本量下的训练和验证表现：

  • 两者都差，可能欠拟合；
  • 训练好、验证明显较差，可能过拟合；
  • 增加样本后差距缩小，收集更多数据可能有帮助；
  • 增加样本后两者都停留在较差水平，可能需要改进特征或模型形式。

这比“数据越多越好”更准确，因为数据质量、代表性和测量方式同样重要。

7 附录C：特征工程及其顺序

操作 目的 注意事项
缺失值填补 避免删除大量记录 参数只从训练数据估计
标准化 让不同量纲具有可比尺度 树模型通常不依赖标准化
哑变量编码 将无序类别转换为数值特征 不要强加大小顺序
合并稀有类别 降低稀疏性和不稳定性 合并规则需有业务含义
对数转换 缓解右偏和极端值影响 处理0和负数并保留逆变换
降维 压缩高度相关的大量特征 可能降低解释直观性

正确顺序是：先划分数据，再在每个训练样本内部估计预处理规则。 把 recipe 放入 workflow，可以让每一折重新估计这些规则，降低泄漏风险。

8 附录D：超参数调优

参数由算法从数据中估计；超参数控制模型结构或学习过程。超参数不能在测试集上选择。基本步骤是：在模型中标记 tune()，在训练集重采样上比较候选值，选定配置后用完整训练集拟合，最后只在测试集评价一次。

# 示例：在训练集内部选择KNN的邻居数。
knn_model <- nearest_neighbor(
  neighbors = tune(),
  weight_func = "rectangular",
  dist_power = 2
) |>
  set_engine("kknn") |>
  set_mode("classification")

knn_workflow <- workflow() |>
  add_recipe(hotline_recipe) |>
  add_model(knn_model)

knn_grid <- tibble(neighbors = c(3, 5, 9, 15, 25, 35))

knn_tuning <- tune_grid(
  knn_workflow,
  resamples = hotline_folds,
  grid = knn_grid,
  metrics = metric_set(roc_auc, sens, spec)
)

show_best(knn_tuning, metric = "roc_auc")

网格不是越密越好。可先用领域知识和粗网格缩小范围，再按需要细化。

9 附录E：类别不平衡、阈值与概率校准

类别不平衡时，建议依次：检查比例和基准；选择敏感度、特异度或PR AUC等指标；结合成本选择阈值；必要时再考虑权重、下采样或SMOTE。采样只能在训练折内部进行。SMOTE不能替代指标与治理成本讨论。

0.50只是常见默认阈值。降低阈值通常提高敏感度但增加误报；提高阈值通常减少误报但增加漏报。阈值也应在训练集重采样预测中确定。

概率模型还应检查校准度。如果被预测为0.70风险的一组工单中长期只有30%实际逾期，则概率没有良好校准。用于资源分配时，应同时检查区分度、校准度和决策价值。

10 附录F：模型审计与负责任使用

公共管理模型会改变资源、注意力和行政负担的分配。部署前至少检查：

  • 不同地区、群体或渠道的漏报率是否差异明显；
  • 历史数据是否包含既有服务不平等或选择偏差；
  • 输出是辅助人工判断，还是直接触发行政决定；
  • 当事人是否有申诉、更正和人工复核渠道；
  • 数据分布变化后由谁监测和更新；
  • 是否保留变量、版本、阈值和决策记录。

变量重要性、回归系数或局部解释工具只能说明模型如何利用相关性，不能自动证明政策因果效应。
